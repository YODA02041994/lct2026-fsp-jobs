## Жёсткие правила

1. **ТЗ и материалы организатора в git не кладём.** По регламенту сведения из ТЗ нельзя передавать третьим лицам.
   Файлы ТЗ лежат локально в `docs/materials/` (папка в `.gitignore`). В документах — только пересказ требований.
2. **Никаких секретов в git:** ключи API, токены, пароли, файлы `.env`. Пример настроек — `.env.example` без значений.
3. **Никаких настоящих персональных данных:** профили участников, контакты рекрутёров, выгрузки вакансий с контактами.
   Демонстрационные профили — выдуманные и явно так помечены.
4. **Источники вакансий — только с разрешённым доступом:** открытые API, RSS, открытые данные. Условия использования
   каждого источника записаны в `docs/03_Источники_вакансий.md`; источник без записи об условиях не подключаем.
   В выдаче всегда есть ссылка на оригинал вакансии.
5. **Чужой код — только с лицензией, которая это разрешает.** Репозиторий без лицензии не копируем. GPL и AGPL не тянем
   в код без решения владельца. Заимствование отмечаем в `docs/02_Готовые_решения.md` и в комментарии у кода.
6. **Достижения участника нельзя выдумывать.** У каждой записи профиля есть уровень доверия: подтверждено источником,
   подтверждено документом или заявлено самим участником. Интерфейс эти уровни не смешивает.
7. **Цифры в документах и презентации — только проверенные:** со ссылкой на источник или на команду, которой их получили.
8. Не переписывать историю git, не делать force-push, не менять видимость репозитория, не удалять issues —
   это действия владельца.
9. Язык документации, issues и сообщений коммитов — русский. В конце коммита — строка `Co-Authored-By` агента.

## Как работать по очереди

- Одна задача = один issue = одна ветка `issue-<N>-кратко` = один PR в `main`. В `main` напрямую — только документы и `STATUS.md`.
- Взял задачу → метка `йода` или `claude` на issue и строка в `STATUS.md` («в работе у …»).
- Закончил или упёрся → обнови `STATUS.md` (что сделано, что проверено, что дальше), сними свою метку,
  поставь метку следующего (`claude` / `йода`) или `ждёт-владельца`, если нужно решение Андрея.
- Перед PR: тесты проходят; интерфейс открыт и проверен руками или снимком экрана.
- Решения только за владельцем: всё про сдачу и публикацию, регистрация приложений во внешних сервисах,
  любые траты, смена архитектуры после 07.10.
