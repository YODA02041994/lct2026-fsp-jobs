## Порядок работы — по весу критериев

| Критерий | Вес | Что делаем |
|---|---|---|
| Механика подбора | 35 % | потребность работодателя → категории и ранжированные кандидаты с обоснованием → приглашение с зарплатой → принятие → раскрытие контактов → статусы; оценка на тестовом наборе пар |
| Тестирование и валидация | 25 % | параметризованные шаблоны заданий с калиброванной сложностью, адаптивный тест, ограничение смены грейда; процедура валидации с цифрами |
| Интерфейс | 10 % | два кабинета, сквозной путь без пояснений, палитра и шрифт из шаблона |
| Техника | 7 % | OpenAPI с кодами ошибок, роли, хэши паролей, docker-compose |
| Полнота и документация | 6 % | путь кандидата целиком, кандидат без истории ФСП, документация отдельным PDF |
| Дополнительно | 7 % | вакансии и отклики, короткие задания, концепция защиты от фиктивных вакансий и ATS |
| Презентация | 10 % | шаблон организатора, слайды 7–11 без изменений |

## Риски

| Риск | Что делаем |
|---|---|
| Объём велик для пяти дней | строим по весу критериев; необязательное — в последнюю очередь |
| Память сервера | один процесс API, база в уже работающем Postgres, без отдельных тяжёлых сервисов |
| Почта не доставляется | письмо через SMTP, если он настроен; иначе ссылка подтверждения показывается на экране с пометкой «демонстрационный режим» |
| Внешняя модель недоступна у жюри | все функции работают без ключей: разбор резюме правилами, задания из банка шаблонов |
| Персональные данные во внешней модели | ФИО и контакты вырезаются до любого внешнего вызова |
