# Валидация решения: процедура и результаты

ТЗ не даёт датасетов и разметки, поэтому проверка построена на синтетическом мире с известной истиной (`backend/app/synth.py`):
у каждого кандидата есть скрытые истинные навыки, грейд и умение θ, а платформа видит только производные — ответы на тест,
заявленный профиль. Метрики считаются скриптами, их можно перезапустить:

```bash
cd backend
../.venv/bin/python ../scripts/validate_testing.py --n 300 --seed 5 --block-size 5 --blocks 2
../.venv/bin/python ../scripts/eval_matching.py --candidates 400 --seed 11
```

## 1. Механика тестирования (критерий № 2)

Модель ответа — Раш с поправкой на угадывание в заданиях с выбором. Через настоящий движок (подбор шаблонов по уровню и стеку,
адаптивные блоки, EAP, решение о грейде) прошли 196 синтетических кандидатов четырёх специализаций со своим банком; банк — 96 шаблонов.
Дата прогона: 06.10.2026.

| Метрика ТЗ | 2 блока × 4 (8 заданий) | **2 × 5 (10) — стенд** | 3 × 5 (15) |
|---|---|---|---|
| Грейд совпал с истинным | 0,57 | **0,62** | 0,63 |
| Грейд в пределах соседнего | 0,95 | **0,99** | 0,98 |
| Средняя ошибка оценки умения, |θ̂ − θ| | 0,56 | **0,53** | 0,47 |
| Согласованность: тот же кандидат, два прохода с разными экземплярами, грейд совпал | 0,45 | **0,55** | 0,58 |
| Дискриминативность, AUC junior/middle | 0,75 | **0,87** | 0,87 |
| AUC middle/senior | 0,87 | **0,89** | 0,86 |
| AUC senior/lead | 0,73 | **0,74** | 0,84 |
| Верное решение о заявленном грейде (завысил → предложено ниже; верно заявил → подтверждён или выше) | 0,87 | **0,85** | 0,89 |

Выбор для стенда — 10 заданий: жюри проходит тест само, и десять минут — предел. Согласованность 0,55 означает, что при повторном
прохождении каждый второй кандидат на границе получает соседний грейд; в пределах соседнего грейда результат стабилен (0,99).
Путь улучшения известен и измерен: удлинение теста до 15 заданий и дополнительные задания при высокой неопределённости θ.

### Устойчивость к утечке заданий

Слабый кандидат (θ = −2,0, истинный junior) заявил middle и «знает» ответы на 40 чужих экземпляров:

| Вариант банка | Средняя оценка θ̂ | Доля получивших middle и выше |
|---|---|---|
| шаблоны с параметрами, без утечки | −1,17 | 0,30 |
| **шаблоны с параметрами, с утечкой** | **−1,17** | **0,30** |
| фиксированный набор заданий, без утечки | −1,16 | 0,35 |
| фиксированный набор, с утечкой | +0,03 | 1,00 |

Утечка ответов на параметризованные задания не меняет оценку: у следующего кандидата другие числа, имена и данные.
Фиксированный набор при той же утечке пропускает слабого кандидата в middle в 100 % случаев.

### Дискриминативность отдельных шаблонов

Для каждого шаблона считается связь «ответил верно → итоговое θ̂» (точечно-бисериальная корреляция). Средняя по банку +0,47.
Шаблоны с корреляцией ниже +0,2 (например, `data_lead_pipeline_idempotent`, `backend_lead_api_breaking_change`) помечены
к пересмотру формулировок. Это и есть механизм калибровки банка по накопленным ответам.

### Пилот с людьми

Запланирован на 08–09.10: участники команды проходят тест, результат сверяется с их реальным уровнем. Результат допишется сюда.

## 2. Механика подбора (критерий № 1)

Синтетический мир из 400 кандидатов; релевантность пары «потребность — кандидат» определяется правилом по **истинным** данным:
специализация совпадает, истинный грейд в пределах ±1, пересечение истинного стека с требуемым не меньше 50 %, зарплатные
ожидания пересекаются. Ранжирование использует только **наблюдаемые** данные. Сравнение с базовыми вариантами:
«слова резюме» — заявленный стек за 1,0 и грейд по самоописанию; «случайно» — случайный порядок внутри специализации.

Результаты записываются сюда после прогона `eval_matching.py` (раздел дополняется 06–07.10).

## 3. Реальный сценарий

Пять потребностей, написанных руками (команда платежей, фронтенд для аналитиков, ML-инженер, автоматизация тестирования,
DevOps в облаке), прогоняются через кабинет работодателя; подборка проверяется глазами. Протокол и снимки экрана — в разделе
документации к сдаче.
