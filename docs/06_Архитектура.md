# Архитектура

Переписана 06.10.2026 под ТЗ. Черновик от 04.10 (агрегация внешних вакансий) снят.

## 1. Роли и сценарии

| Роль | Что делает |
|---|---|
| Кандидат | регистрируется с подтверждением почты, заполняет профиль или загружает резюме PDF, проходит опрос и тест, получает категорию, настраивает приватность и согласия, связывает профиль с ФСП ID, получает приглашения, откликается на вакансии |
| Работодатель | заполняет профиль компании, описывает потребность, получает подборку с обоснованием, ищет по банку кандидатов, направляет приглашения с зарплатой, публикует вакансии, работает с откликами |
| Оператор | заводит записи реестра достижений ФСП (имитация реестра), проверяет загруженные документы, смотрит метрики |

Контакты кандидата закрыты для работодателя до принятия приглашения или собственного отклика кандидата.

## 2. Компоненты

```
frontend/   веб-приложение для обеих ролей: Vue 3 без сборщика, свой CSS в палитре ФСП, шрифт Montserrat
   │  HTTP, JSON
backend/    FastAPI: /api/v1, OpenAPI с кодами ошибок
   ├── auth        почта + пароль (argon2), подтверждение адреса, JWT, роли; OIDC-клиент для ФСП ID
   ├── profiles    профиль, резюме из PDF, PDF-профиль, приватность, согласия
   ├── testing     банк шаблонов, генераторы экземпляров, адаптивный сеанс, оценка θ, грейд, ограничение смены
   ├── matching    потребность → категории → ранжирование → обоснование; подборки с версиями
   ├── contacts    приглашения, отклики, статусы, раскрытие контактов
   ├── vacancies   вакансии работодателей, отклики, короткие задания
   ├── fsp         имитация реестра ФСП, связь с ФСП ID, уровни доверия достижений
   └── nlp         словарь технологий с синонимами; внешняя модель — по желанию, с обезличиванием
db/         PostgreSQL 16: одна база, миграции Alembic
scripts/    синтетические данные, валидация тестирования, оценка подбора
docs/       документация; итоговый PDF собирается из docs/
```

Монолит с явными слоями и слабо связанными модулями (ТЗ допускает). Фронтенд отделён от бэкенда: общается только через
документированное API, поэтому его можно заменить или вынести.

## 3. Выбор технологий

| Часть | Выбор | Почему |
|---|---|---|
| Бэкенд | Python 3.12, FastAPI, SQLAlchemy 2, Alembic, Pydantic | описание API строится автоматически; знакомый стек |
| База | PostgreSQL 16 | реляционная модель, полнотекстовый поиск по стеку и описаниям |
| Фронтенд | Vue 3 (ESM-сборка с CDN, без Node), свой CSS | отдельное веб-приложение без этапа сборки; быстро и легко проверить |
| Пароли и токены | argon2, JWT с коротким сроком, токены подтверждения почты одноразовые | требование безопасности ТЗ |
| ФСП ID | OIDC-клиент с настраиваемым издателем; в демонстрации — встроенный издатель-заглушка | совместимость с Keycloak без самого Keycloak на сервере |
| Почта | SMTP из настроек; без SMTP — ссылка подтверждения показывается на экране с пометкой «демонстрационный режим» | жюри запускает локально без ключей |
| Внешняя модель | OpenAI-совместимая точка из настроек; без ключа — правила | плюс по ТЗ; обязательный запуск без ключей |
| PDF | извлечение текста — pdfminer; сборка PDF-профиля — fpdf2 со встроенным шрифтом | чистый Python |
| Запуск | docker-compose: db, api, web (nginx отдаёт фронтенд и проксирует API) | воспроизводимый запуск по инструкции |
| Стенд | тот же код как служба systemd за nginx `/fsp/`, база — в уже работающем Postgres сервера | на сервере мало памяти, лишних контейнеров не ставим |

Чего нет намеренно: микросервисов, очередей, отдельного поискового сервера, резидентной модели эмбеддингов.

| Сущность | Главные поля |
|---|---|
| `user` | почта, хэш пароля, роль, подтверждён ли адрес, даты |
| `candidate` | псевдоним, ФИО, контакты, город, стаж, роли, гибкие навыки, зарплатные ожидания, формат работы, приватность, согласия, `fsp_id`, `grade`, `grade_changed_at`, `specialization` |
| `candidate_skill` | технология, источник (профиль, резюме, тест), подтверждена ли тестом |

| `template` | компетенция, специализации, формат, сложность b, генератор, статус (черновик, проверен) |
| `test_session` | кандидат, заявленный грейд, блоки, θ, итоговый грейд, решение (подтверждён, предложен ниже, предложен выше) |
| `test_item` | сеанс, шаблон, зерно, экземпляр, ответ, верно ли, время |
| `employer`, `employer_user` | компания, описание, направление, контакты |
| `need` | текст потребности, специализация, грейд, стек, зарплата от–до, формат, город |
| `selection`, `selection_version` | подборка и её версии: фильтры, результаты с оценками и обоснованиями |
| `invitation` | работодатель, кандидат, версия подборки, предложение, зарплата от–до, способ связи, статус, даты |
| `vacancy`, `application` | вакансия с зарплатой от–до, отклик и его статус |
| `short_task`, `short_task_answer` | короткие задания от работодателей и ответы кандидатов |
| `fsp_registry_event`, `fsp_registry_result` | имитация реестра ФСП: событие (номер в календаре Минспорта, дисциплина, уровень), результат участника |
| `achievement` | запись в профиле: тип, дисциплина, уровень, дата, срок, уровень доверия, документ, подпись |

## 5. Интеграция с реестром ФСП (схема для документации)

Сейчас (прототип): имитация реестра внутри базы; кандидат связывает профиль с ФСП ID через OIDC-вход у издателя-заглушки;
по идентификатору подтягиваются результаты из имитации реестра; записи получают уровень «подтверждено источником».
Кандидат без истории ФСП видит в профиле раздел «История ФСП отсутствует», в ранжировании слагаемое достижений равно нулю,
остальные слагаемые работают.

После хакатона: издатель-заглушка заменяется на Keycloak ФСП (тот же протокол), имитация реестра — на API реестра;
схема записи о достижении (`docs/04`, раздел 8) остаётся.

## 6. Безопасность и персональные данные

- Пароли — argon2; токены подтверждения и сброса одноразовые с коротким сроком; JWT с ролью.
- Разграничение: кандидат видит только своё; работодатель — обезличенные профили до принятия приглашения.
- Согласия: на обработку и на показ профиля работодателям — раздельно, с датой и версией текста.
- Внешней модели передаётся текст без ФИО, контактов и адресов: они вырезаются до вызова.
- Журнал действий с персональными данными: кто и когда открыл контакты.
