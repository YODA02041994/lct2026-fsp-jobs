# Черновик архитектуры

Написан 04.10.2026 по названию задачи, до выдачи ТЗ. 05.10 сверяется с ТЗ; до 07.10 может меняться, после — замораживается.

## 1. Что строим

Площадка с тремя ролями:

| Роль | Что делает |
|---|---|
| Участник ФСП | ведёт профиль с подтверждёнными достижениями, ищет вакансии, видит подбор с объяснением, откликается |
| Работодатель | размещает вакансию, указывает требуемый уровень достижений, ищет участников, приглашает |
| Оператор ФСП | подтверждает записи профиля, видит табло метрик |

Отличие от обычного агрегатора: у каждой записи о достижении есть уровень доверия и способ проверки,
а подбор учитывает достижения и объясняет, что именно совпало.

## 2. Схема

```
источники вакансий ──► сбор ──► нормализация ──► дедупликация ──► каталог (Postgres)
  Работа России          по расписанию   роль, грейд, навыки,     ключ-блок +            │
  Хабр Карьера                           зарплата, формат         сходство текста         │
  freehire                                                                                ▼
  вакансии работодателей ───────────────────────────────────────────────────────►  поиск и фильтры
                                                                                          │
участник ──► профиль ──► записи о достижениях ──► подтверждение ──► подписанная запись    │
               │            (разряд, результат,      оператором        + страница         │
               │             рейтинг)                ФСП               проверки, QR       │
               └──────────────────────────► подбор «участник ↔ вакансия» ◄────────────────┘
                                              оценка + объяснение
работодатель ──► вакансия с требуемым уровнем ──► поиск участников ──► приглашение
```

## 3. Состав и выбор технологий

| Часть | Выбор | Почему |
|---|---|---|
| Сервер | Python, FastAPI | быстро пишется, описание API строится автоматически, знаком по основному треку |
| База | PostgreSQL | одна база на каталог, профили, поиск и векторы |
| Поиск | полнотекстовый поиск Postgres с русским стеммингом, `pg_trgm` для опечаток, `pgvector` для смысла | без отдельного поискового сервера: на нашем сервере мало памяти |
| Интерфейс | страницы, собираемые на сервере, с частичным обновлением | один процесс, нет отдельной сборки; решение пересматривается, если ТЗ потребует отдельного клиентского приложения |
| Сбор вакансий | отдельная задача по расписанию, по одному модулю на источник | источник можно отключить, не трогая остальное |
| Подписи записей | Ed25519, запись в формате JSON с подписью | проверяется на публичной странице без входа |
| Развёртывание | Docker Compose: сервер, база, сборщик | запуск одной командой |

Чего в прототипе нет намеренно: отдельного поискового сервера, очередей сообщений, микросервисов.

## 4. Данные

| Сущность | Главные поля |
|---|---|
| `vacancy` | источник, внешний идентификатор, ссылка на оригинал, название, работодатель, ИНН, роль, грейд, навыки, зарплата от и до, валюта, формат работы, город, дата публикации, первое и последнее появление, статус, требуемый уровень достижений, дисциплина, льгота |
| `vacancy_copy` | связь вакансии с её копиями в других источниках |
| `employer` | название, ИНН, сайт, признак проверки |
| `athlete` | учётная запись участника, регион, видимость профиля |
| `achievement` | тип (разряд, результат соревнования, рейтинг), дисциплина, уровень, дата, срок действия, источник, уровень доверия, подпись, признак «скрыто» |
| `evidence` | документ или ссылка, подтверждающие запись |
| `skill` | название, синонимы |
| `application`, `invitation` | отклик участника и приглашение работодателя, статусы |

Уровни доверия записи о достижении:

| Уровень | Что означает | Участвует в подборе |
|---|---|---|
| подтверждено источником | запись сверена с данными ФСП или другого первоисточника | да |
| подтверждено документом | оператор проверил загруженный документ | да |
| заявлено участником | проверки не было | нет, показывается с пометкой |

## 5. Подбор

Оценка складывается из объяснимых частей; веса показаны на экране и уточняются после ТЗ:

| Часть | Что сравнивается |
|---|---|
| Навыки | доля требуемых навыков вакансии, которые есть в профиле |
| Смысловая близость | вектор профиля и вектор вакансии |
| Достижения | уровень и дисциплина против требуемого уровня вакансии; учитываются только подтверждённые записи |
| Условия | зарплата, формат работы, город |
| Свежесть | возраст вакансии |

В карточке подбора: совпавшие навыки, недостающие навыки, какое достижение закрыло требование, чего не хватает до вакансии.

## 6. Проверка достижения работодателем

1. Оператор подтверждает запись → сервер подписывает её своим ключом.
2. У записи появляется постоянная ссылка и QR-код.
3. По ссылке открывается страница без входа: что подтверждено, кем, когда, действует ли, подпись верна или нет.
4. Участник может скрыть запись или отозвать ссылку.

## 7. Что решает ТЗ

| Вопрос | Варианты |
|---|---|
| Даст ли ФСП данные участников или доступ к ним | сверка с источником либо только подтверждение документом |
| Нужна ли сторона работодателя | полный кабинет либо только каталог и профиль |
| Требования к интерфейсу | страницы с сервера либо отдельное клиентское приложение, мобильная версия |
| Требования к источникам вакансий | свои сборщики либо допустимы готовые открытые каталоги |
| Формат сдачи | репозиторий, стенд, контейнер, запись работы |

## 8. Где размещать стенд

На сервере, где стоит стенд основного трека, занята почти вся подкачка. До выбора — замер памяти.
Запасной путь — отдельный небольшой сервер; это трата, решение за владельцем.
